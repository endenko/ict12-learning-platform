# Reproduce completion audit (standalone, no repository)

Prerequisites: Node24, Python3 with openpyxl, Google Chrome at `/opt/google/chrome/chrome`; run from project root. Local browser tooling is pinned in `testing-tools/package.json` (Playwright1.65.0); install with `npm install --prefix testing-tools` if absent. No browser login or paid service is needed for semantic fixtures.

1. `python3 release-audit/full-review/apply-corrections.py` reproduces current banks from included round1 baselines plus exact31 patches. It never reads/writes the database or legacy bank. Do not run the older `release-audit/correct-content.py` alone and call that the final bank; it generates only round1. If used, apply this completion step afterward.
2. `python3 release-audit/full-review/build-evidence.py` compiles **already-authored**448 item notes into the fingerprinted ledger. This script does not perform semantic review or generate verdict prose. The TSV notes, source catalog, textbook references and before/after patches are the evidence; count checks alone do not certify content.
3. Run `node tests/content-audit-unit.js`, `node tests/content-audit-browser.js`, `node tests/unit.js`, `node tests/upgrade-unit.js`, `node tests/readiness-unit.js`, `python3 tests/readiness-semantics.py`, `node tests/readiness-browser-semantics.js`.
4. With this deployment operator's existing secure environment configured locally (never print/share `.env` or any password), run a local adapter: `LOCAL_DEV=1 PORT=3006 node --env-file=.env server.js`. Then `node --env-file=.env tests/readiness-e2e.js` and `node --env-file=.env tests/content-live-audit.js`. These create clearly marked TEST accounts/classes, run sequential representative attempts, then lock TEST users/disable TEST assignments and restore teacher settings. Inspect cleanup verdicts; do not assume a failed cleanup succeeded.
5. For authorized production verification, set `TEST_BASE=https://ict12-learning-platform.vercel.app` for the same two test scripts, then run `tests/readiness-final-smoke.js`, `tests/readiness-live-artifacts.js`, `python3 tests/content-excel.py` and `tests/content-preservation.js` (Node scripts use the same secure env). This deliberately creates only TEST records, not load-test traffic. It does not delete history or restore production destructively.
6. `scripts/prepare-deploy.py` freezes the16 runtime files. Upload changed SHA files and deploy **same existing project/team through the sanctioned Vercel connector**, with production target only as authorized. If403, create a fresh approval link, save it to `VERCEL_APPROVAL_LINK.txt`, return it and stop; no CLI/temp-project/repository workaround.
7. `python3 scripts/archive-source.py` creates the safe source/evidence archive. It excludes credentials, env, private snapshots/receipts and real student datasets. The source archive includes answer banks for the operator; it is **not a public student download**.

`tests/content-preservation.js` additionally compares against the private pre-audit snapshot receipt on the original operator box, reporting only counts/booleans. That receipt and student/password-hash data are intentionally absent from the source archive; recreating one elsewhere requires authorized DB operator access. Backup validation is not a destructive restoration drill and not large-scale load certification.
